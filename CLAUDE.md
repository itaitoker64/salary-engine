# salary-engine — working notes for Claude

Hebrew-language payroll validation engine. It recomputes each עובד מדינה payslip
from the חוקה (the Progim workbook) and reports where the real slip disagrees.
The audience is מנהלת הגמלאות, so a number on screen has to survive being
questioned in a meeting.

## The standing rule: never flag a legitimate worker

A false positive costs more than a miss. Every validation rule must trace to a
cell in the Progim workbook — a sheet, a formula, a table. Do not reverse-
engineer a rule from the payroll data and do not keep a rule that "mostly"
works: if a check fails for workers who are in fact paid correctly, drop it and
say so.

Rules that cannot be sourced belong in `docs/PROGIM_FIXES.md` as a defect to fix
in the workbook, not as a patch in the engine.

## Two Claudes share this repo

A second session works the same repository on
`claude/salary-validation-highlighting-s22hlj` and merges to `main` often. The
SessionStart hook prints the delta before you touch a file — **read it**. It
lists which files `main` changed that this branch also touched, which is where
the conflicts will be.

Assume `main` has moved. Assume overlapping work exists. Check before building
something that may already be there, and never force-push over a branch you did
not read first.

## Handoff protocol

A session that adds commits must leave `docs/HANDOFF.md` describing the state it
is leaving behind, and commit it. The Stop hook blocks the turn once if the file
still points at an older HEAD.

Write it for a Claude that has this repo and nothing else — no memory of the
conversation. Cover:

- **State** — branch, whether it is merged, what `main` has that it does not.
- **What changed and why** — the reasoning, not the diff. Git already has the diff.
- **Verified how** — the command that was run and the number it produced.
- **Open** — decisions waiting on the user, known-wrong things, traps.

Keep the `<!-- head: <sha> -->` marker on line 1 current; the hooks read it.

## Verify before you claim

- `python3 -m pytest tests/ -q` — 20 tests.
- `node --check engine.js` — the browser engine has no test suite.
- Re-run a real file and quote the bucket counts. Numbers from a run, never from
  reasoning about the code.

Sample גולמי files live in `/root/.claude/uploads/<session-id>/`. The 0108 file
(22,422 slips) is the reference: the dashboard partition must sum to exactly
22,422.

## Architecture facts that bite

- `engine.js` is a hand-port of `main.py`. A rule changed in one and not the
  other means the website and the CLI disagree. Change both.
- `index.html` and `salary_frontend.html` carry the **same** embedded script.
  Both, every time.
- `component_rules.json` is generated by `tools/extract_rules.py` from the
  Progim workbook, but it is also hand-edited. Regenerating overwrites manual
  fixes — diff before you regenerate.
- The neutralization chain (`err_cat`) is a strict partition: each invalid
  full-timer lands in exactly one bucket. Priority order and dashboard column
  order must match, in `tools/unified_report.py` **and** both front-ends —
  moving a column without moving the priority produces a right-looking table
  with wrong numbers.
